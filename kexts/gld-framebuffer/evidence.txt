对应 E6 已证写入 Q 的16字节记录：
+0 u16 <- ECX(type=0x2000)
+4 u32 <- R9D=0；E7中作为0x1e0步长的图像组索引。
+8 u32 <- 第7参数=0；E7中作为0x20步长的level索引。
+c u32 <- 第8参数=0；其他层级语义尚未完全恢复。
因此仅接受上述 renderbuffer 零组/零level/零附加层级条件。
+2/+3 没有已证语义约束，代码不读取；测试故意置0xa5。
普通 texture/cube/数组/层附件暂不支持，不凭名称推断非零值。

实现范围：
 vgf_create 借用有长度 FQ/FD，拒绝输出/可写视图别名和地址溢出。
 backend resolve 显式完成系统 token->texture 映射；share 在 ensure 前校验。
 ensure_backing 返回真实已准备 vgc image；格式/尺寸/深度/样本数严格核验。
 vgc_framebuffer_attach 再次校验实际 image 类型及 share，防回调错误归属。
 独立候选 FBO attach/load 成功才替换 active target，失败不改旧目标。
 FD 只在失败时置 failed bit0；成功清 pending bit0/failed bit0，保留其余位。
 未知 pending 位拒绝，FD 所有 texture token 和 FQ 始终不改。
 旧 target 与 image 由预分配节点持强引用；释放失败可在后续 load/destroy 重试。
 destroy 失败保留包装，停止新 load/get，直到所有引用及 backend lease 清理成功。
 vgf_target_get 返回借用已提交 vgc FBO；绑定 context 后 context 自行持强引用。
 此模块没有系统 GLD 导出，没有 CPU 假后端作为正式 backend。

测试：
