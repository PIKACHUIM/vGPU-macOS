_MTLDevice 直接子类：最小负向加载诊断构建契约（2026-11-16）

结论
“initWithAcceleratorPort: 记录入口然后返回 nil”足以作为正常 loader 的负向初始化终点，但裸写这两句不是完整安全实现：MRC 会遗失 alloc 的对象；ARC 隐式释放或显式 [self release] 可能进入尚未初始化的基类 dealloc。本轮得到并严格构建一个不访问私有 ivar、不调用私有基类初始化的 MRC 候选：入口 fprintf → object_dispose(self) → return nil。仅编译、链接及静态检查通过；尚未加载、安装或执行候选，不能宣称运行时安全已实证，更不能称 Metal 可用。

3. init/dealloc 不能忽略
-[_MTLDevice init]：0x7FF80D34378A 起。先 super init，然后创建三条 dispatch queue，构造 MTLLibraryBuilder、pipelineLibraryBuilder，创建 loader/pool 和其它 Foundation 状态。并非空 init；初始化对象依赖的 C++ 构造函数未在本轮递归穷尽，因此不选择调用 super init 作为“零副作用”方案。
-[_MTLDevice initWithAcceleratorPort:]：0x7FF80D43D5DA–0x7FF80D43D5F1。把原 selector 作为参数发另一个 ObjC 消息，随后清零返回值。本轮未解码这个转发 selector，不能声称可安全调用 super 的同名方法。摘录在 ret 后带有后续无标签指令，分析边界仅到上述 ret。
-[_MTLDevice dealloc]：0x7FF80D43D6E3 起。+0x1d0/+0x1d8 有非空检查；但 0x7FF80D43D742/74E/75A 加载 +0x118/+0x120/+0x128，分别无非空检查地调用 dispatch_release。这不支持对仅 alloc 的零状态对象执行普通 release；dispatch_release 不能按 objc_msgSend(nil) 来推理。
-.cxx_construct：0x7FF80D4464C3–64E5，只清零上述 once_flag 并返回 self；没有资源分配或 GPU 操作。

4. 可实现最小候选
实际源码：out/metal-failclosed-candidate.m
SHA256：83eabdcfe91bf20d98165cb9578fc1c99e6d38c4b4c7bff0e8026b89d30305fb

最小声明只包含已核验关系和方法，不伪造完整 private header：
@interface _MTLDevice : NSObject
- (instancetype)initWithAcceleratorPort:(io_service_t)service;
@end
@interface VGPUMetalFailClosedDevice : _MTLDevice
@end

@implementation VGPUMetalFailClosedDevice
- (instancetype)initWithAcceleratorPort:(io_service_t)service {
    fprintf(stderr, "VGPU_METAL_DIAGNOSTIC_INIT service=0x%x result=nil GPU_NOT_EXECUTED\n", service);
    object_dispose(self);
    return nil;
}
@end

必须以 MRC 编译；源码 #error 阻止 ARC。没有自定义 ivar，不声明 MTLDevice/MTLDeviceSPI 协议，不实现任何假资源/队列方法；ObjC 非脆弱 ABI 的实际 superclass 大小由运行时元数据决定，不能把本地简化声明当作真实基类布局。候选无 ivar访问，故不依赖伪造布局。
object_dispose 是公开 ObjC runtime 函数：销毁实例并释放对象存储，不发送 -dealloc；会执行运行时销毁清理。适用前提是本机已核验基类构造仅清零且没有相应 C++ 析构、候选没有创建/持有资源、self 尚未暴露出去。此用法严格限定为本机负向诊断，不用于任何可用设备实现，不推广为一般 ObjC 初始化失败习惯用法。
没有 IOObjectRetain/Release(service)，因为传入的是 wrapper 借用的服务句柄，候选没有获取所有权；绝不关闭或 deallocate 它。
没有 [super init]、[super initWithAcceleratorPort:]、[self release]，没有 IOServiceOpen/IOConnectCall*。

只记录再 return nil 的 MRC 版本会泄漏每次 alloc；重复热插拔/重枚举可能扩大泄漏，不采用。
另一个可实现但较弱的方案是只覆盖 +allocWithZone: 返回 nil，验证类分配入口但不会进入 initWithAcceleratorPort:，不满足端口入口验证目标。
本候选清理方案已静态审查但未执行；后续应先在隔离测试进程中验证 runtime 的实际分配大小、重复构造/失败销毁不崩溃，再进行正常 loader 验证。不得直接据本报告称动态安全通过。

7. 真实加载验证能证明什么
若以后在新进程中通过标准 Metal loader，看到唯一候选入口标记并确认它返回 nil，则证明路径选择/信任/可执行文件加载/ObjC 类查找/继承准入/服务 wrapper 条件/alloc/端口入口这一条负向链走通。
依据已有 loader 反汇编：init 返回 nil 时不调用 _setAcceleratorService:、MTLAddDevice；因此无需实现后续 MTLDevice 完整接口就可完成负向测试。仍应确认没有候选被加入设备数组，不能把原有其它设备存在与候选成功混淆。
若只 NSBundle/dlopen 手工加载或直接调用自定义 init，只能证明手工路径，不能证明 gpu_bundle_find_trusted 或系统服务发现；stderr 无记录也不能单独定位为继承失败。
整个方案不验证 type5，也不需要该 user-client；type5 是 MTLIOAccelDevice 路线的独立问题。未来真正 Metal 功能仍需实现资源、shader、queue、同步和渲染语义。
